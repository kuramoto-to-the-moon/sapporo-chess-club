# ヘッダー Headroom の設計メモ

hide-on-scroll ヘッダーはこのサイトで最も凝った JS（3ファイル・約160行）。
将来の改修時に因果関係を再発見しなくて済むよう、各部品が「なぜ存在するか」と
「どうあるべきか」の判断をここに固定する。

## 挙動仕様

- ヘッダーは `sticky top-0`。下スクロールで隠れ（`data-state=hidden` → `-translate-y-full`）、上スクロールで再表示
- ページ上部 100px 以内では常に表示
- アンカージャンプ（ページ内 / ハッシュ付きロード）の間は隠さない

## 構成部品と存在理由（因果マップ）

```
Header.astro <script>           … 状態機械 (data-state の付け外し)
  └─ lib/scroll-observer.ts     … スクロール観測 (方向・位置・maxY)
  └─ "headroom:freeze" イベント  … HamburgerMenu.astro から発火
globals.css scroll-padding-top  … アンカー着地位置の補正
```

| 部品 | 存在理由 (これを消すと起きる不具合) |
|---|---|
| `scroll-observer.ts` の rAF スロットル | scroll イベント毎フレーム多発 → 処理間引き。消すと低速端末でジャンク |
| 同 visualViewport 高さ変化の無視 | **iOS Safari の URL バー開閉**が scroll イベントを発火する。消すとページ端でヘッダーがちらつく |
| 同 DELTA=8px の方向デッドゾーン | タッチ操作の指の揺れで up/down が振動する。消すとヘッダーがバタつく |
| `Header` の TOP_THRESHOLD=100 | ページ先頭付近で隠すと戻る手段がない。UX 保険 |
| 同 `y >= maxY - 4` ガード | **iOS のラバーバンド**（最下部で弾む）が y を往復させ方向が反転する。消すと最下部でヘッダーが明滅 |
| freeze 機構（安定フレーム検出） | アンカージャンプは「大きな下スクロール」としてイベントに現れる → 着地した瞬間にヘッダーが隠れる。時間ベース (setTimeout) でなく「scrollY が 5 フレーム不動」で解除するのは、端末速度に依存しないため |
| freeze のトリガー (a): `headroom:freeze` CustomEvent | ハンバーガーメニュー内のページ内アンカーをクリックした時。dialog を閉じた直後にジャンプが走る |
| freeze のトリガー (b): `window.location.hash` 検査 | クロスページのアンカー遷移（別ページから `/#contact` 等）。ロード直後にブラウザが自動スクロールする |
| `scroll-padding-top: 57px` (globals.css) | sticky ヘッダー高さ分、アンカー着地位置を下げる。ヘッダー高さを変えたらここも追従が必要 |

**暗黙の結合:** HamburgerMenu → Header は CustomEvent 経由の疎結合。
イベント名 `headroom:freeze` が唯一の契約。

## 検討済みの代替案と却下理由

| 代替案 | 判定 | 理由 |
|---|---|---|
| CSS scroll-driven animations (`animation-timeline: scroll()`) | ❌ | スクロール**位置**には反応できるが**方向**ベースの show/hide は表現できない。headroom の置き換えにならない |
| ライブラリ (headroom.js 等) 導入 | ❌ | 依存追加の割に iOS quirk 対応は自前実装と同等。現状の方が小さい |
| freeze を setTimeout に簡素化 | ❌ | スクロール所要時間は端末・距離依存。短いと途中で切れ、長いと操作を無視する。安定フレーム検出が正解 |
| DELTA / ガードの削除 | ❌ | 各行が実機の不具合1個に対応（上表）。「一見冗長」はすべて再現手順のある症状の修正 |
| ヘッダー常時表示化（headroom 全削除） | ⭕ 唯一の有効な簡素化 | -160行 + 結合解消。代償はモバイルで常時 57px 占有 |

## 結論（あるべき姿）

1. **中間的な簡素化は存在しない。** 全部品が実機症状に紐付いており、部分削除は不具合の再導入。選択肢は「現状維持」か「headroom 廃止（常時表示）」の二択
2. **現状維持を採用。** モバイル中心のサイトで縦 57px の価値が大きく、実装は安定稼働中
3. 将来、この機構がバグの温床になった場合は、**修理を重ねず常時表示化へ倒す**（このメモの表を見て「直せそう」と部分改修しないこと）
4. ヘッダーの高さを変更する時は `scroll-padding-top` (globals.css) の追従を忘れない
